# Админка almaty-travel.kz

Адрес: **https://adirov.github.io/almaty-travel-review/admin/**

Админка — [Sveltia CMS](https://github.com/sveltia/sveltia-cms), та же, что у школы (snow-school.kz/admin/). Сервер и база данных не нужны: админка открывается в браузере и сохраняет правки прямо в этот репозиторий на GitHub.

## Почему так

Сайт almaty-travel.kz — это готовые HTML-страницы (снимок старой CMS плюс наши правки скриптами из `tools/`), сборки из шаблонов нет. Поэтому админка правит не HTML, а небольшие файлы `content/pages/<язык>/<страница>.md`, а скрипт `tools/cms.py` переносит правки в страницы. Страницы, которые не трогали, не меняются ни на байт.

## Что можно править

| Раздел админки | Что можно |
|---|---|
| Туры и страницы (русский / English) | 48 страниц на каждом языке: частные туры, туры, зима, «О нас», контакты и другие. SEO-заголовок и описание для Google, заголовок на странице, текст под заголовком, фото в тексте, фотогалереи (добавить, убрать, поменять порядок и подписи) |
| Статьи (гид) | создать и править статьи раздела «Гид», английская и русская версии, черновик / опубликовано |

Новые страницы туров из админки не создаются (только статьи). Удаление в админке отключено.

Что правится только в коде: главная страница (кроме SEO-заголовка, описания и H1), блок «Что входит в стоимость», FAQ, «Похожие туры», меню, футер, публичная оферта, страница «Частный водитель-гид» (pages/26), а также текст старых страниц со сложной вёрсткой (tours/23, 113, 398, 810). У них в админке поле «Текст страницы» пустое: там можно менять SEO и фото, текст — через код.

### Текст страницы

- «Цитата» — выделенное вступление тура (на сайте это абзац `tour-intro`).
- «Заголовок 2» / «Заголовок 3» — подзаголовки (например «День 1»).
- Строка `{{фото}}` — место, где стоит сетка «Фото в тексте». Если строки нет, фото встанут в конце текста.

### Фото

Загруженные фото сохраняются в `assets/images/cms/`, сразу переводятся в WebP и уменьшаются до 1600 px. Уменьшенную копию 640 px для сетки делает сборка. Подпись к фото (alt) пишите всегда: она нужна Google и незрячим.

## Что происходит после «Сохранить»

1. Админка делает коммит в ветку `codex/demo` («CMS: изменено …»).
2. GitHub Actions (`.github/workflows/cms.yml`) за 2–4 минуты:
   - переносит правку в HTML-страницы (`tools/cms.py apply`), статьи — через `tools/articles.py`;
   - прогоняет SEO-правки (`tools/seo_round2.py`) и сверяет файлы админки со страницами (`tools/cms.py export`);
   - обновляет проверочный сайт https://adirov.github.io/almaty-travel-review/ ;
   - пересобирает публичную версию в ветку `live-site`.
3. **На almaty-travel.kz правки появятся только после выкладки** (деплой через Plesk, `tools/deploy.php`). Сама админка хостинг не трогает.

## Как войти

Нужен аккаунт GitHub с правом записи в репозиторий `adirov/almaty-travel-review`.

1. Эмиль (владелец репозитория) входит своим аккаунтом. Артуру: GitHub → `adirov/almaty-travel-review` → Settings → Collaborators → Add people → аккаунт Артура. Артур принимает приглашение из письма.
2. Токен (один раз): GitHub → Settings → Developer settings → Personal access tokens → **Fine-grained tokens** → Generate new token.
   - Repository access: **Only select repositories** → `adirov/almaty-travel-review`.
   - Permissions → Repository → **Contents: Read and write**. Срок: 1 год.
3. Открыть админку → «Войти с помощью токена доступа» → вставить токен. Браузер запомнит вход. Токен никому не пересылать.

Кнопку «Войти через GitHub» можно включить так же, как у школы (Cloudflare Worker sveltia-cms-auth), см. docs/CMS.md в репозитории ski-school.

## Для разработчика

- `python3 tools/cms.py export .` — HTML → файлы админки (пишет только то, что отличается). Запускать после ручных правок страниц, если не хочется ждать Action.
- `python3 tools/cms.py apply . content/pages/ru/<файл>.md` — файл админки → страница (и её копия в `summer/`).
- `build_live.py` в самом конце вызывает `cms.apply_live`: SEO-заголовок, описание и H1 из админки главнее старых SEO-патчей.
- Нужны `pyyaml` и `pillow` (`pip install pyyaml pillow`).
- HTML в репозитории с CRLF: скрипты читают и пишут с `newline=''`.
- Админка и `content/` на almaty-travel.kz не выкладываются (SKIP в `build_live.py`).
